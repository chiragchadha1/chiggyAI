# Chiggy AI portfolio update pack

Use this note as the quick entry point when updating `chiggy.ai` or drafting public-facing portfolio material.

## Which voice to use

- Portfolio homepage, case studies, project descriptions, LinkedIn updates: use [[chirag-professional-voice]].
- X/Twitter launch threads, casual build notes, DMs, captions: use [[chirag-personal-voice]].
- If the writing sounds too clean, run the [[humanizer]] pass.
- Before publishing/saving something durable, run the [[chirag-output-quality-gate]] rubric.

## Strongest portfolio through-line

Chirag has been building toward the same thesis for years:

1. **Anlyst** framed the problem: fragmented personal data creates decision fatigue.
2. **chiggyOS** became the personal knowledge layer: journals, meetings, notes, dumps, and project docs feeding a living wiki.
3. **Atlas/Hermes** made it operational: an always-on agent that reads context, writes back to the vault, and handles async work through Telegram.
4. **HubSpot MCP/dev tooling** proves the professional side: building tools that other developers and agents depend on at real scale.

The portfolio should make that through-line obvious without over-explaining it.

## Copy rules for portfolio updates

- Start with what exists and what it does.
- Use concrete mechanisms: Obsidian vault, Hermes agent, Telegram interface, cron jobs, Google/GitHub integrations, wiki absorb flow.
- Show one or two real workflows end-to-end instead of listing every feature.
- Preserve the distinction between product owner / system designer / dogfooder and hand-coding every primitive.
- Do not inflate side projects into companies unless the artifact supports it.
- Do not mention Seated publicly unless Chirag explicitly approves it. Resy / Amex risk still applies.

## Design direction

Good starting references for `chiggy.ai`:

- **Vercel:** clean developer credibility, strong typography, restrained black/white.
- **Linear:** precise dark-mode product feel, good for showing systems and workflows.
- **Stripe:** polished narrative landing page, useful for making infrastructure feel accessible.
- **Raycast:** command-first/productivity energy, useful for Atlas as an operator tool.
- **Framer:** portfolio/creative polish when the page needs more personality.

Do not clone these. Borrow posture: hierarchy, density, restraint, and product clarity.
