## The problem

The best tables in NYC open and vanish in seconds. I wanted to learn to code something
genuinely hard, so I started building a bot that could grab them the instant they dropped.

## What I built

It started as a slow browser-automation script (Playwright). The competitive drops demanded
speed, so I profiled the network traffic and re-architected it into an API-first tool, then
added a pre-solve timing technique: prepare the slow verification step a minute ahead of the
drop, cache the result, then fire the booking the instant the table opened.

<Diagram name="presolve-timeline" />

That took bookings down to under two seconds from drop time. Around the engine I built a
real product: login and customer profiles, CRUD request management, a customer intake form,
and Stripe authorization holds that only charge on a successful booking and release on
failure. It went from a rough script to a CLI tool to a full-stack service in a short
window.

const token = await presolveChallenge();        // ~30s, done at T-60s
await waitUntil(dropTime);                       // hold the cached token
const table = await book({ slot, token });       // fires in < 2s at T-0`}</Code>

## What happened

One friend's Instagram story brought 50+ people into my DMs overnight, and I had paying
customers within the week. Instant product-market fit.

## Lessons

<Callout label="What it taught me">
Building something people want is necessary but not sufficient. Sustainability and risk
management matter just as much as shipping. The model carried platform risk that made it
hard to scale responsibly, so I wound it down as a deliberate decision, and it reshaped how
I think about building durable products.
</Callout>
